# TVMbot workspace instructions

You are working on the production repository for The Villa Managers (TVM).

## Product architecture

- `/` is the public TVM website: a Bali villa marketing agency plus The Bali Furniture.
- `/afni/` is Afni's public freelancer portfolio. It has no admin login.
- `/admin/` is the protected staff HQ.
- `/owner/` is the protected, read-only owner portal.
- `index.js` is the Node.js HTTP/API entrypoint.
- `brain.js` routes authenticated internal messages to the local Hermes API.
- `hermes-client.js` is the localhost-only Hermes Responses API client.
- `agent-tools.js` and `.hermes/skills/tvm-operations/` are the narrow business-operations bridge.
- `assistant.js` contains deterministic reminders, memory, and schedules.
- `channels/` contains the existing WhatsApp and Telegram integrations.
- `villa-data.js`, `auth-users.js`, `audit.js`, and `notion.js` contain private operational data logic.
- `website/` contains public static pages; `admin/` contains protected interfaces.
- `ops/` contains Nginx and GitHub-to-VPS deployment automation.

TVM is a villa marketing agency. Do not describe it as a villa management company. Owners submit villas for marketing toward monthly, yearly, or long-term tenants. Owners retain final control over tenant approval, contracts, property operations, rent, and deposits unless a written agreement explicitly says otherwise.

## Safety and privacy

- Never print, copy, commit, or expose `.env`, API keys, bot tokens, passwords, cookies, private keys, WhatsApp sessions, or personal identity documents.
- Never place contracts, passport/ID files, guest contact information, payment proofs, or deposit records on the public website.
- Private documents belong in restricted Google Drive locations; the dashboard may store protected links only.
- Do not invent villa, guest, owner, payment, contract, or business data. Use placeholders only when clearly labeled.
- Do not reuse the TVMbot WhatsApp or Telegram credentials in another process. Two consumers using the same bot/session can conflict.
- The Hermes gateway may expose its API server on `127.0.0.1:8642` only. Do not enable Hermes' Telegram or WhatsApp platform adapters; TVMbot owns those channels.
- When invoked through TVMbot, use `tvm-operations` for operational mutations. Do not edit code, deploy, or change server configuration from a messaging conversation.
- Do not delete production data, reset Git history, or overwrite uncommitted work.

## Working rules

1. Read `git status` and the relevant files before changing anything.
2. Keep changes scoped to the user's request and preserve the current architecture.
3. Use `rg` for searches and `apply_patch` for deliberate source edits.
4. Run syntax checks and relevant tests before publishing.
5. Never expose private routes or APIs without server-side authorization.
6. Keep local, GitHub `main`, and `/root/tvmbot-v4` synchronized when the user asks to publish.
7. Production deploys use `ops/sync-and-deploy.sh`; verify `/health` after deployment.
8. Ask before enabling a new public endpoint, messaging channel, scheduled autonomous task, or destructive operation.

## Useful checks

```bash
npm ci
node --check index.js
node --check assistant.js
node --check brain.js
node --check villa-data.js
npm start
```

The production service is managed by PM2 as `tvmbot-v4`. Nginx serves the public pages and proxies protected/API routes to the local Node.js service.
